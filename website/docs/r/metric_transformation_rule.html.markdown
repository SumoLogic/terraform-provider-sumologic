# sumologic_metric_transformation_rule
Provides a [Sumo Logic Metric Transformation Rule][1]. A metric transformation rule selects incoming metrics with a selector, sets how long they are retained, and can optionally aggregate or rewrite their dimensions to produce transformed metrics.

## Example Usage

Retain selected metrics for 400 days without transforming them:

```hcl
resource "sumologic_metric_transformation_rule" "example" {
  name     = "Retain metrics store data"
  selector = "_sourceCategory=metricsstore"
}
```

Aggregate on a dimension and add a suffix to the metric name. The original metrics are not stored, and the transformed metrics are kept for 8 days:

```hcl
resource "sumologic_metric_transformation_rule" "aggregated" {
  name                          = "Aggregate metrics"
  selector                      = "_sourceCategory=metricsstore"
  enabled                       = true
  retention                     = 0
  transformed_metrics_retention = 8

  dimension_transformation {
    transformation_type = "AggregateOnTransformation"
    aggregate_on        = ["metric"]
  }

  dimension_transformation {
    transformation_type  = "AddOrReplaceTransformation"
    dimension_to_replace = "metric"
    value                = "{{metric}}_aggregated"
  }
}
```

## Argument reference

The following arguments are supported:

- `name` - (Required) Name of the metric transformation rule.
- `selector` - (Required) Selector that chooses the metrics the rule applies to, for example `_sourceCategory=metricsstore`.
- `enabled` - (Optional) Whether the rule is enabled. Defaults to `true`.
- `retention` - (Optional) Retention period in days for the metrics chosen by the selector. Valid values are `8`, `400`, and `0` (do not store). `0` is only valid when at least one `dimension_transformation` is defined. Defaults to `400`.
- `transformed_metrics_retention` - (Optional) Retention period in days for the transformed metrics generated by the rule. Valid values are `0`, `8`, and `400`. Must be `0` when no `dimension_transformation` is defined. Defaults to `0`.
- `dimension_transformation` - (Optional) An ordered list of dimension transformations applied by the rule. Can be repeated. See [dimension_transformation](#dimension_transformation) below.

### dimension_transformation

- `transformation_type` - (Required) The type of transformation. Valid values are `AggregateOnTransformation` and `AddOrReplaceTransformation`.
- `aggregate_on` - (Optional) List of dimensions to aggregate on. Required when `transformation_type` is `AggregateOnTransformation`.
- `dimension_to_replace` - (Optional) The dimension to add or modify. Required when `transformation_type` is `AddOrReplaceTransformation`.
- `value` - (Optional) The value for the dimension. It can reference other dimensions, for example `{{metric}}_aggregated`. Required when `transformation_type` is `AddOrReplaceTransformation`.

~> **NOTE:** The order of `dimension_transformation` blocks is preserved and sent to the API in the order written.

## Attributes reference

In addition to all arguments above, the following attributes are exported:

- `id` - The identifier of the metric transformation rule.
- `created_at` - Creation timestamp (RFC3339, UTC).
- `created_by` - Identifier of the user who created the rule.
- `modified_at` - Last modification timestamp (RFC3339, UTC).
- `modified_by` - Identifier of the user who last modified the rule.

## Import

Metric transformation rules can be imported using the id, e.g.:

```
terraform import sumologic_metric_transformation_rule.example 0000000000000001
```
